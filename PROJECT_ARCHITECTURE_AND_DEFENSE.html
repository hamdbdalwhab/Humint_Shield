01 • EXECUTIVE SUMMARY

1.0 الملخص التنفيذي

1.1 المشكلة

المؤسسات تستثمر في الجدران النارية وأنظمة كشف الاختراق، لكن أخطر قناة اختراق تبقى السلوك البشري: بريد تصيّد، رسالة SMS، رمز QR ملصق على جدار، فلاشة USB متروكة، أو مكالمة صوتية منتحلة. المشكلة ليست غياب الوعي فقط، بل غياب قياس سلوكي قابل للتكرار يربط كل تفاعل بموظف محدد، وبقناة محددة، وبدرس تدريبي فوري.

1.1.1 تشتّت القنوات

أدوات البريد لا تقيس QR، وأدوات QR لا تقيس USB أو المكالمات، فلا توجد صورة موحدة للمخاطر.

1.1.2 غياب القياس العادل

النتائج الثابتة لا تراعي صعوبة السيناريو ولا تكرار التعرض، فتصبح الدرجات غير قابلة للمقارنة.

1.1.3 ضعف الأدلة التدريبية

بدون سجل زمني موحد يصعب إثبات ما حدث، ومتى، وعلى أي جهاز، وبأي نتيجة تعليمية.

1.2 الحل

HUMINT Shield منصة تدريب توعوي قائمة على الموافقة، تجمع محاكاة متعددة القنوات، وتتبعًا زمنيًا دقيقًا، وتدريبًا فوريًا، ولوحة إدارة عربية RTL. الرسائل المحاكاة لا تسرق كلمات المرور، وصفحات الهبوط تُفصح عن طبيعة الاختبار، وكل إرسال حقيقي يظل مشروطًا بإعدادات المزود وتفويض صريح.

1.2.1 محاكاة متعددة القنوات

Email، SMS، QR/Quishing، USB، Vishing، CEO Pretexting، WhatsApp، وVoice — مع نموذج حملة موحّد وسجل تتبع موحّد.

1.2.2 قياس سلوكي تكيفي

نظام Elo يبدأ من 1000، ويوزّع أوزانًا حسب القناة وصعوبة القالب، مع تصنيف سلوكي على نافذة 90 يومًا.

1.2.3 سلسلة أدلة قابلة للتدقيق

كل فتح، نقرة، إرسال، تقرير، وإكمال تدريب يُضاف إلى سجل زمني دقيق، مع تشفير الحقول الحساسة.

1.2.4 واجهة عربية RTL

React 18 وTypeScript وVite وMUI، مع خط Cairo، وتخطيط RTL كامل، ولوحات حية للمخاطر والنتائج.

الأثر العملي: تحويل الوعي الأمني من محاضرة إلى تجربة قابلة للقياس؛ كل موظف يمتلك درجة تكيفية، وكل حملة تنتج سلسلة أدلة، وكل قناة تُختبر ضمن نفس الإطار. النتيجة ليست “نجح أو فشل” فقط، بل صورة واضحة عن المخاطر السلوكية قبل أن تتحول إلى حادث حقيقي.

رسالة الدفاع: المشروع ليس أداة هجوم؛ هو منصة محاكاة مصرّح بها، لا تحتفظ بكلمات المرور، وتُظهر إفصاحًا واضحًا، وتستخدم بيانات تدريبية قابلة للتدقيق.
02 • SYSTEM OVERVIEW

2.0 نظرة عامة على النظام

2.1 الصورة الكبيرة

HUMINT Shield تطبيق ويب متكامل يفصل الواجهة العربية التفاعلية عن طبقة API مركزية، ثم يربط المنطق الخلفي بقاعدة بيانات موحدة ومزودي القنوات الخارجيين. المستخدم النهائي يتفاعل مع صفحة تدريب أو حملة محاكاة، بينما يدير المدير الحملات والنتائج من لوحة RTL. كل تفاعل يمر عبر FastAPI، ويُسجَّل في قاعدة البيانات، ويُحدّث درجة الموظف وسلسلة الأدلة.

2.3 الطبقات الأربع

كل طبقة لها مسؤولية واضحة، ولا تختلط مع غيرها؛ هذا هو أساس قابلية الاختبار والصيانة.

2.3.1 طبقة الواجهة — UI

React 18 + TypeScript + Vite + MUI
  • 33 ملف .tsx في الصفحات (28 صفحة تشغيل + 5 اختبارات)، و23 ملفًا في المكونات (21 مكوّنًا + 2 اختبارات).
  • RTL كامل وخط Cairo، مع حماية مسارات عبر ProtectedRoute.
  • Axios client، Redux Toolkit، React Query، ورسوم Chart.js/Recharts.

2.3.2 طبقة المنطق — Logic

FastAPI + Domain Services
  • 124 معالج API موزّع على 22 ملفًا في backend/app/api/v1.
  • خدمات الحملات، التتبع، الإشعارات، المصادقة، والتقارير.
  • Rate limiting، CORS، correlation IDs، ومعالجة أخطاء موحدة.

2.3.3 طبقة الذكاء — AI

AI-assisted + Behavioral Intelligence
  • ai_service.py يدعم أي مزود متوافق مع OpenAI Chat Completions.
  • تنقية HTML وتوليد قوالب عربية آمنة، بدون fallback صامت.
  • classification_engine.py وelo_engine.py للتصنيف والدرجات التكيفية.

2.3.4 طبقة البيانات — Data

SQLAlchemy Async + Alembic + Redis
  • PostgreSQL 16 في الإنتاج، وSQLite في التطوير والاختبار.
  • 15 نموذج ORM في 11 ملفًا، و19 ترحيلًا، مع تشفير AES-256-GCM للحقول الحساسة.
  • Redis/Celery للمهام الخلفية، وقيود تتبع فريدة لكل حملة وموظف.

6.4 أسئلة وأجوبة للمناقشة

6.4.1 لماذا ثماني قنوات وليس البريد فقط؟

لأن المهاجم لا يختار قناة واحدة. تغطية البريد وSMS وQR وUSB والصوت والواتساب تكشف نقاط الضعف الحقيقية، وتسمح بمقارنة سلوك الموظف عبر سياقات مختلفة.

6.4.2 كيف تمنعون استخدام المنصة كأداة هجوم؟

المنصة قائمة على الموافقة، ولا تحتفظ بكلمات المرور، وتُظهر إفصاحًا، وتشترط إعدادات مزود وتفويضًا. كل حملة مرتبطة بتنظيم وموظفين معروفين، وكل حدث قابل للتدقيق.

6.4.3 كيف تعمل درجة Elo؟

تبدأ من 1000، ولكل قناة وزن، ولكل نتيجة نسبة تأثير، وتضاعف صعوبة القالب الحركة. النتيجة تُقيَّد بين 0 و2000، وتُترجم إلى نطاق صعوبة ومستوى خطر.

6.4.4 أين البيانات الحساسة وكيف تُحمى؟

كلمات المرور المُدخلة لا تُخزَّن كنص واضح، والحقول الحساسة تُشفَّر بـAES-256-GCM، والمصادقة JWT، وكلمات مرور المستخدمين bcrypt، والوصول محكوم بالأدوار والتنظيم.

6.4.5 ما الإضافة الأكاديمية؟

الجمع بين محاكاة متعددة القنوات، وقياس سلوكي تكيفي، وسلسلة أدلة زمنية، وواجهة عربية RTL، ضمن منصة واحدة قابلة للتشغيل والتدقيق — وليس مجرد أداة إرسال بريد.
